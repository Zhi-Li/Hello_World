# First-run checks on the target Mac

**Performance 1.3.3:** compare ScreenGateService's disk writes during a minute of ordinary screen use: periodic history saves should occur about twice per minute, apart from immediate owner/network changes. After stopping protection and allowing any pending save to finish, clean stopped state should not keep writing. Paused protection still records calendar usage and checkpoints it. Keep a restriction active and confirm unchanged five-second inspections do not repeatedly apply network configuration. Enable/add a network service and confirm it is restricted within five seconds. Pause/quit and verify restoration. Owner changes and normal restarts must retain their state; abrupt termination may lose the last uncheckpointed ordinary usage (about 30 seconds when writes are healthy). Recheck CPU/disk activity on the target Mac; automated tests do not measure its responsiveness.

**Click menu 1.3.2:** with another app active and ScreenGate controls locked/closed, click the shield. Its menu should show version 1.3.2, today's total and split, and owner controls below. Hold the menu open: counters should refresh about every two seconds. Clicking owner controls must still open the password prompt. Hovering alone must not show a usage panel or tooltip. Repeat on each monitor and with full-screen apps. At midnight the summary must update to the new date.

**Installer 1.3.1:** on macOS 27, install from a browser-downloaded ZIP. Approve the executable when requested. Confirm both installed ScreenGate plists have no com.apple.quarantine attribute and the daemon registers. Retry after interrupting before initialization, and after the password is created but registration fails: the existing password and history must survive. Try Recover.command and a reboot. A subsequent bootstrap failure must print the launchd-log command. macOS 27 launchd policy is not exercised by the macOS 15 build runner.

These live checks have not been run on a person's Mac. Run them before relying on ScreenGate for unattended enforcement. Native compilation and unit tests are separate from these checks.

1. **Install.** For the compiled ZIP, extract the whole download and run Install.command; Xcode and Command Line Tools are not required. The remote build runs the native unit tests and verifies both architectures and signatures before producing this ZIP. If using the source project instead, build tools with Swift 5.7+ are required (Xcode 14.2 or compatible Command Line Tools on Monterey). Confirm the menu bar shield appears, the owner window can close and reopen, and Cmd-Q asks for the owner password. For compatibility testing, run the same universal app on an Intel Mac with **macOS 12.7.6**, an Apple silicon Mac with macOS 12+, and a newer macOS version.
2. **Protect controls.** An incorrect password must fail. Five incorrect attempts must cause a temporary lockout. The menu and Cmd-Q must ask for a fresh owner password to stop. Losing focus and closing the owner window must lock the controls.
3. **One-minute test.** Temporarily remove school windows and leave an all-day after-school window. Set the allowance to one minute and reset today's usage. Use the awake/unlocked screen. After about one minute, confirm an internet request fails. Test a fresh website load, not a cached page. Confirm owner's controls remain accessible while offline.
4. **Restore.** Pause: internet should return within a few seconds and usage should stop increasing. Resume: because the allowance is used, internet should block again. Increase the limit: internet should return. A service already disabled before the test must remain disabled after restoration.
5. **Lock and sleep.** Reset usage. Record it, lock the screen for a minute, then unlock. It should not have increased by that minute. Repeat for display sleep and Mac sleep. Video viewing while unlocked should count. Check the screen-status label after unlocking and with each external-display setup.
6. **School boundaries.** Create a short in-school window covering now and verify counting stops and internet returns. On its end boundary, after-school counting should resume. An overnight window should apply to the next morning of its starting weekday. School priority must be independent of window order.
7. **Daily reset.** For a development/test Mac only, observe a midnight crossing using a short allowance. The next day's usage should start at zero. Avoid changing the clock on an everyday Mac solely for this check. Also verify the timezone shown in the Mac's settings is the one intended for scheduling.
8. **Restart and exit.** With partial usage, restart the Mac: today's usage should persist. With the allowance used, blocking should persist in after-school mode. Force-quit the UI: the daemon must continue enforcing. Owner-approved Stop & Quit should restore internet; reopen/reboot should show stopped protection until Resume.
9. **Interfaces and accounts.** Repeat with Ethernet, USB tethering, VPN software, and fast user switching if you use them. A newly enabled network service should be disabled within five seconds while blocked. These are machine-wide controls, so owner use on another account contributes to the same daily allowance.
10. **Offline recovery and removal.** While blocked, run Recover.command as administrator; verify internet returns and protection stays stopped. Test Uninstall.command restores connections and removes the jobs. Reinstall and choose the final password, schedule, and allowance.

11. **Calendar.** Select today, another recorded day, and a day without records. Browse across month/year boundaries and return with Today. In-school and after-school time should appear separately alongside the total, including while the internet is blocked. Cross a school boundary and confirm only the corresponding row grows on each side. Pause should stop allowance usage but keep recording both calendar categories. Reset the allowance counter: the calendar total and split must remain unchanged. Edit schedules and confirm earlier readings do not change. A gap between scheduled modes should appear separately as Outside scheduled modes. Close/reopen and reboot: recorded dates and splits must persist. On upgrade, total-only records show breakdown unavailable; a day with mixed old/new recordings shows Earlier unsplit time. Legacy allowance-only records remain labeled after-school only. The first full-day recording date shows its recording start time.
12. **Today-only extension.** Use the one-minute setup until blocked, then add 15 minutes. The effective allowance should become 16 minutes and connections should return without zeroing usage. Add a custom amount, confirm additions accumulate, then restart and confirm today's extra time persists. At a natural local-midnight crossing, the regular daily allowance should return while history remains. While paused or stopped, adding time must not resume protection.

13. **Menu-bar click summary.** Close and lock owner controls, then click the shield. Today's total and in-school/after-school split should appear in hours/minutes/seconds, match the calendar within a few seconds, and keep refreshing without unlocking. Repeat while offline and while protection is paused. Sleep/lock the Mac, then wake/unlock and confirm the summary updates. At midnight it must show the new day's total and split rather than yesterday's. Disconnecting the background service should show Unavailable; restoring it should recover the summary. Changing settings or accessing history must still require the owner password.

Keep Recover.command available on the Mac before testing blocking. If any check fails, leave protection stopped and record the error displayed in owner controls or in `/Library/Application Support/ScreenGate/service.log`.
