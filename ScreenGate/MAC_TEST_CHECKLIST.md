# First-run checks on the target Mac

These live checks have not been run on a person's Mac. Run them before relying on ScreenGate for unattended enforcement. Native compilation and unit tests are separate from these checks.

1. **Install.** For the compiled ZIP, extract the whole download and run Install.command; Xcode and Command Line Tools are not required. The remote build runs the native unit tests and verifies both architectures and signatures before producing this ZIP. If using the source project instead, build tools with Swift 5.7+ are required (Xcode 14.2 or compatible Command Line Tools on Monterey). Confirm the menu bar shield appears, the owner window can close and reopen, and Cmd-Q asks for the owner password. For compatibility testing, run the same universal app on an Intel Mac with **macOS 12.7.6**, an Apple silicon Mac with macOS 12+, and a newer macOS version.
2. **Protect controls.** An incorrect password must fail. Five incorrect attempts must cause a temporary lockout. The menu and Cmd-Q must ask for a fresh owner password to stop. Losing focus and closing the owner window must lock the controls.
3. **One-minute test.** Temporarily remove school windows and leave an all-day after-school window. Set the allowance to one minute and reset today's usage. Use the awake/unlocked screen. After about one minute, confirm an internet request fails. Test a fresh website load, not a cached page. Confirm owner's controls remain accessible while offline.
4. **Restore.** Pause: internet should return within a few seconds and usage should stop increasing. Resume: because the allowance is used, internet should block again. Increase the limit: internet should return. A service already disabled before the test must remain disabled after restoration.
5. **Lock and sleep.** Reset usage. Record it, lock the screen for a minute, then unlock. It should not have increased by that minute. Repeat for display sleep and Mac sleep. Video viewing while unlocked should count. Check the screen-status label after unlocking and with each external-display setup.
6. **School boundaries.** Create a short in-school window covering now and verify counting stops and internet returns. On its end boundary, after-school counting should resume. An overnight window should apply to the next morning of its starting weekday. School priority must be independent of window order.
7. **Daily reset.** For a development/test Mac only, observe a midnight crossing using a short allowance. The next day's usage should start at zero. Avoid changing the clock on an everyday Mac solely for this check. Also verify the timezone shown in the Mac's settings is the one intended for scheduling.
8. **Restart and exit.** With partial usage, restart the Mac: today's usage should persist. With the allowance used, blocking should persist in after-school mode. Force-quit the UI: the daemon must continue enforcing. Owner-approved Stop & Quit should restore internet; reopen/reboot should show stopped protection until Resume.
9. **Interfaces and accounts.** Repeat with Ethernet, USB tethering, VPN software, and fast user switching if you use them. A newly enabled network service should be disabled within five seconds while blocked. These are machine-wide controls, so owner use on another account contributes to the same daily allowance.
10. **Offline recovery and removal.** While blocked, run Recover.command as administrator; verify internet returns and protection stays stopped. Test Uninstall.command restores connections and removes the jobs. Reinstall and choose the final password, schedule, and allowance.

Keep Recover.command available on the Mac before testing blocking. If any check fails, leave protection stopped and record the error displayed in owner controls or in `/Library/Application Support/ScreenGate/service.log`.
